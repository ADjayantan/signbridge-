# SignBridge visual update — 11 October 2026

Implemented a warm ivory, deep teal and copper interface, with Fraunces display type and the existing Sora interface font. Font loading has system fallbacks. Home has a clear Start/Join area, visible quick tools and a decorative Three.js hand-landmark sculpture. The sign workspace places camera capture beside result review on desktop, with camera first on mobile. Optional message destinations and AI remain below the core workflow.

## Graphics and accessibility

- Three.js 0.186.1 loads in a separate dynamic chunk. The scene is decorative and hidden from assistive technology; it is neither a detected hand nor a sign example.
- The scene unmounts when the camera starts. Pixel ratio is capped at 1.5 and animation at 30 fps. Hidden/offscreen scenes pause; reduced motion retains a still rendering.
- WebGL unavailable/context loss retains an SVG fallback. GPU resources, observers and animation frames are released on unmount.
- Native labelled controls, three-step keyboard focus navigation, visible speech controls and existing routes remain intact. Camera errors scroll inside the preview so Retry stays reachable on narrow screens.

## Verification

- `npm run check`: Node tests, UI tests and production build passed. Additional focused scene lifecycle and Home/workspace tests passed after adding the WebGL availability guard.
- `npm run build:public`: passed; local research model artifacts excluded. Vite reports large application/Three chunks; Three is lazy-loaded rather than merged into the main bundle.
- Actual in-app browser: desktop 1440×1000; phone layouts 390×844 and 320×740; no horizontal overflow on Home or the sign workspace. These are responsive browser checks, not physical phone tests.
- Actual camera start removed the decorative scene; End session restored the idle scene and released the preview. The measured preview was dark. At 320px the dark-warning overlay scrolled and Retry was successfully clicked. This does not establish live sign recognition accuracy.
- Keyboard Enter on the Text & voice step focused the message textarea. Typing enabled Speak my message; Undo returned the draft to empty. Speech sound was not evaluated in this visual update.
- Reduced-motion browser emulation rendered the scene; temporary media and viewport overrides were reset afterwards.
- Five focused lifecycle tests cover pause/visibility/motion/size, resource cleanup, canceled lazy initialization, renderer failure/context loss and a platform without WebGL.
